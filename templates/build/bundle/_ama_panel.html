{% comment %} The AMA editing panel, used in three places: - the metadata drawer on the bundle page, opened from a label in the Files card (fetched by AJAX) - the standalone per-file page - the standalone collection-defaults page It covers both scopes. `is_default_scope` means these are the collection's defaults, inherited by every file in the collection that has no values of its own, including files uploaded later. Otherwise it is one file's values. The three sections are tabs rather than an accordion: they are peers a user moves between, and Simulation Configuration alone is 17 fields, which made the accordion's one-open-at-a-time shuffle feel like the page was jumping. Tab order is deliberate and matches how the values behave in practice - Model Metadata and Simulation Configuration describe the run and are normally shared across a collection, File Description describes one file's slice and normally is not. Each section carries its own scope control, so a user can hold Model Metadata at collection level while giving this file its own File Description. The data-* attributes on the root are the contract with the drawer's JS: it reads them to know whether a save succeeded and which file to reopen after the reload that follows. {% endcomment %}
